## LeetCode 739 — Daily Temperatures

For every index `i`, find the first future index `j` where `temperatures[j] > temperatures[i]`. Answer is `j - i`, or `0` if no such index exists.

### Brute force

Scan forward from every index — `O(n²)`.

### The optimization: a monotonic decreasing stack

Instead of repeatedly searching forward, keep the indices of temperatures still waiting for something warmer. The stack stays monotonically decreasing from bottom to top.

```js
function dailyTemperatures(temperatures) {
  const answer = new Array(temperatures.length).fill(0)
  const stack = [] // indices, not temperatures

  for (let i = 0; i < temperatures.length; i++) {
    while (
      stack.length &&
      temperatures[i] > temperatures[stack[stack.length - 1]]
    ) {
      const prevIndex = stack.pop()
      answer[prevIndex] = i - prevIndex
    }
    stack.push(i)
  }

  return answer
}
```

The current temperature resolves every unresolved temperature it's warmer than. Once it's `<=` the stack's top, it can't resolve anything else — stop and just push.

### Why store indices, not temperatures?

`temperatures[index]` already gives the value — storing the index also lets you compute `i - prevIndex` for the answer.

### Why it's still O(n)

A `while` inside a `for` looks like it could be `O(n²)`, but every index is **pushed exactly once and popped at most once** — total work across the whole run is bounded by `2n`.

| | Time | Space |
| --- | --- | --- |
| Daily Temperatures | O(n) | O(n) |

## The Bigger Shift

Across sliding window, prefix sum, and monotonic stack, the real skill isn't memorizing solutions — it's recognizing what the problem needs from the past:

```text
Need contiguous range + a condition   → Sliding Window
Need a subarray sum/count             → Prefix Sum
Need the most recent unresolved item  → Stack
Need the next greater/smaller item    → Monotonic Stack
```
