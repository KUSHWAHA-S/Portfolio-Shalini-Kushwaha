## Recap: Pattern 1 — Frequency Map

Mental trigger:

```text
Need counts?
      ↓
HashMap<Character, Frequency>
```

Stores: `element → frequency`

Problems this fits: Valid Anagram (LeetCode 242), First Unique Character (LeetCode 387), Ransom Note (LeetCode 383), Group Anagrams (LeetCode 49).

## Pattern 2 — Lookup Map ("Remember What I've Seen")

Instead of asking:

> How many times have I seen this?

We ask:

> Have I seen this before — and where?

| | Frequency Map | Lookup Map |
| --- | --- | --- |
| Stores | `value → count` | `value → index` (or other info) |
| Example | `'a' → 3` | `7 → index 0` |
| Question | "How many?" | "Have I seen this? Where?" |

## Worked Problem: Two Sum (LeetCode 1)

```text
nums = [2, 7, 11, 15]
target = 9

answer = [0, 1]    // 2 + 7 = 9
```

### Work the framework first

- **Input?** An array of numbers and a target.
- **Output?** The indices of the two numbers that add up to the target.
- **Operation?** Not counting, not reversing — *searching* for a complement.

### The insight

Walk the array one number at a time.

At `2`: can you answer yet? No — you don't know what's still coming.
At `7`: can you answer now? **Yes** — because you've already seen `2`, and `2 + 7 = 9`.

That sentence — *"I have already seen..."* — is the trigger. Whenever the answer depends on something encountered earlier in the traversal, reach for a HashMap.

> **Your turn:** standing on the first element, `2`, with `target = 9` — what number do you need to complete the target?
> `Need _______`
>
> Answer: **`7`** — `target - current`. That's the entire trick behind Two Sum.

### Solution

Brute force — check every pair:

```js
function twoSum(nums, target) {
  for (let i = 0; i < nums.length; i++) {
    for (let j = i + 1; j < nums.length; j++) {
      if (nums[i] + nums[j] === target) return [i, j]
    }
  }
  return []
}
```

Time: **O(n²)** · Space: **O(1)**

One-pass HashMap — trade space for time:

```js
function twoSum(nums, target) {
  const seen = new Map() // value -> index

  for (let i = 0; i < nums.length; i++) {
    const complement = target - nums[i]
    if (seen.has(complement)) return [seen.get(complement), i]
    seen.set(nums[i], i)
  }

  return []
}
```

Time: **O(n)** · Space: **O(n)**

### Interview nugget

Check **before** you store, not after. If you `set` the current number first, `nums = [3, 3]` with `target = 6` would let a number match against itself at the same index. Checking first, then storing, guarantees a match can only come from a number seen *earlier* in the array.

## Golden Rule

> What information do I need to remember while traversing?

Answering that honestly points to the right data structure more reliably than memorizing pattern names.
