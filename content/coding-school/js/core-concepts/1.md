## 1. Execution Context

Every function execution gets an execution context containing conceptually:

```text
Lexical Environment
Variable Environment
This binding
```

Execution flow:

```text
Global Execution Context
        ↓
Function Call
        ↓
Function Execution Context
```

## 2. `this`

`this` is determined mainly by **how a function is called**, not where it is defined.

```js
obj.fn()        // this = obj
fn()            // globalThis / undefined in strict mode
fn.call(obj)    // this = obj
fn.apply(obj)   // this = obj
fn.bind(obj)()  // this = obj
```

### Arrow functions

Arrow functions **don't have their own `this`** — they capture `this` lexically from the surrounding scope.

## 3. `call`, `apply`, `bind`

### Signature

```js
fn.call(thisArg, arg1, arg2)
fn.apply(thisArg, [arg1, arg2])
fn.bind(thisArg, arg1, arg2)
```

| | Executes immediately? | Arguments |
| --- | --- | --- |
| `call` | Yes | Individual |
| `apply` | Yes | Array-like |
| `bind` | No | Individual |

`bind()` returns a **new function** with permanently bound `this`.

## 4. Closures

A closure occurs when a function retains access to variables from its lexical scope even after the outer function has finished.

```js
function outer() {
  let count = 0

  return function () {
    count++
    return count
  }
}
```

The returned function still has access to `count`.

Uses: data privacy, function factories, memoization, callbacks, event handlers.

## 5. Hoisting

Declarations are processed before execution.

```js
console.log(a) // undefined
var a = 10
```

`let`/`const` are also hoisted conceptually but remain in the **Temporal Dead Zone** until initialization.

```js
console.log(a) // ReferenceError
let a = 10
```

Function declarations can be called before their declaration.

## 6. Temporal Dead Zone

```js
{
  // TDZ starts
  console.log(x) // ReferenceError

  let x = 10
  // TDZ ends
}
```

The variable exists in the lexical environment but cannot be accessed before initialization.

## 7. `var` vs `let` vs `const`

| | `var` | `let` | `const` |
| --- | --- | --- | --- |
| Scope | Function | Block | Block |
| Redeclare | Yes | No | No |
| Reassign | Yes | Yes | No |
| TDZ | No | Yes | Yes |

`const` means the **binding** cannot be reassigned, not that the referenced object is immutable.

```js
const arr = []
arr.push(1) // fine
```

## 8. Primitive vs Reference

### Primitives

```text
string, number, bigint, boolean, undefined, null, symbol
```

Immutable.

### Objects

```text
object, array, function, Map, Set, ...
```

Variables contain references to objects.

```js
const a = {}
const b = a

a === b // true
```

### Why `typeof null === "object"`

`null` is a primitive — not an object — despite `typeof null` returning `"object"`. This is a bug from the very first JS engine (1995): values were stored internally as a type tag plus a value, and objects used the tag `0`. `null` was represented as the all-zero pointer, which happened to share that same tag — so `typeof` misreports it. It's been kept ever since because fixing it would break existing code across the web.

Proof it's still a primitive:

```js
typeof null          // "object"  (the historical quirk)
null instanceof Object // false   (it isn't actually an object)
Object.getPrototypeOf(null) // TypeError — no prototype chain
```

## 9. Type Coercion

```js
"5" + 2  // "52"
"5" - 2  // 3
true + 1 // 2
```

`+` has string concatenation behavior. Other arithmetic operators generally convert to numbers.

### Strict equality

`===` checks type + value without implicit coercion. Prefer `===` over `==` unless you intentionally need coercion.

## 10. `Object()`

Primitive values can be temporarily boxed when accessing properties/methods.

```js
"hello".length
```

Conceptually:

```text
string primitive
      ↓
temporary String object
      ↓
.length
```

`Object(value)` explicitly converts a primitive into its wrapper object — `Object("hello")`, `Object(10)`, `Object(true)`. This is why `Object(this)` appears in many array-method polyfills.

## 11. Prototype

Objects can inherit properties through their prototype chain.

```text
obj
 ↓
obj.[[Prototype]]
 ↓
another object
 ↓
Object.prototype
 ↓
null
```

Property lookup: check the object, not found → check the prototype → continue up the chain. `obj.toString()` may come from `Object.prototype`.

## 12. `__proto__` vs `prototype`

### `prototype`

Property of **constructor functions**, used when creating instances.

```js
function Person() {}
Person.prototype
```

### `__proto__`

Accessor that exposes an object's own prototype: `person.__proto__`. Prefer the modern APIs:

```js
Object.getPrototypeOf(person)
Object.setPrototypeOf(person, proto)
```

## 13. Functions Are Objects

A function can have properties:

```js
function foo() {}

foo.name
foo.length
foo.prototype
```

Functions inherit from `Function.prototype` — that's why `foo.call()`, `foo.apply()`, `foo.bind()` exist.

## 14. Higher-Order Functions

A function that receives a function, or returns a function.

```js
map, filter, reduce, forEach

function multiplier(x) {
  return function (y) {
    return x * y
  }
}
```

## 15. `map`

```js
arr.map(callback) // (value, index, array)
```

Transform every existing element into a new value. Returns a **new array**.

```js
[1, 2, 3].map(x => x * 2) // [2, 4, 6]
```

## 16. `filter`

```js
arr.filter(callback) // (value, index, array)
```

Select elements based on a condition. Returns a **new array** containing original values.

```js
[1, 2, 3].filter(x => x > 1) // [2, 3]
```

## 17. `reduce`

```js
arr.reduce(callback, initialValue) // (accumulator, currentValue, currentIndex, array)
```

Reduce multiple values into one result.

Without an initial value, the first existing element becomes the accumulator, so the callback starts from index `1`. An empty array with no initial value throws `TypeError`.

## 18. Array Iteration & Mutation

Most array iteration methods conceptually: capture length → iterate indexes → check property exists → read current value → callback.

`arr.push(...)` during iteration generally doesn't add the new element to the original iteration range, because the length was already captured. But modifying an **unvisited existing index** can affect what a later iteration reads.

## 19. Sparse Arrays

```js
const arr = [1, , 3]
```

Index `1` is a **hole** — different from `[1, undefined, 3]`, where index `1` exists and contains `undefined`. Check with `1 in arr`.

## 20. Event Loop

```text
Call Stack
    ↓
Web APIs / Host APIs
    ↓
Queues
    ↓
Event Loop
    ↓
Call Stack
```

**Microtasks:** `Promise.then`, `queueMicrotask`, `MutationObserver`.
**Macrotasks/Tasks:** `setTimeout`, `setInterval`, DOM events.

After a task finishes, the engine processes pending **microtasks before moving to the next task**.

## 21. Promise

```text
pending → fulfilled
pending → rejected
```

Once settled, state cannot change again. `promise.then(...)`, `.catch(...)`, `.finally(...)` — callbacks execute as **microtasks**.

## 22. Async / Await

```js
async function foo() {
  const result = await promise
}
```

`async` always returns a Promise. `await` pauses the async function's continuation — it **doesn't block the JS thread**. The continuation runs through the microtask mechanism after the awaited promise settles.

## 23. Shallow vs Deep Copy

### Shallow copy

```js
const copy = { ...obj }
```

Nested objects still share references.

### Deep copy

```js
structuredClone(obj)
```

Creates a deep clone for supported structured-cloneable values. Be careful with `JSON.parse(JSON.stringify(obj))` — it loses/changes certain values and doesn't support many object types.

## 24. Debounce vs Throttle

### Debounce

Execute after events stop for a specified period. Useful for search input, resize, validation.

### Throttle

Execute at most once within a specified interval. Useful for scroll, mouse movement, continuous events.

## 25. Currying

Transform `fn(a, b, c)` into `fn(a)(b)(c)`.

```js
const add = a => b => c => a + b + c
```

## 26. Immutability

Instead of:

```js
state.user.name = "A"
```

create a new reference:

```js
setState({
  ...state,
  user: {
    ...state.user,
    name: "A",
  },
})
```
