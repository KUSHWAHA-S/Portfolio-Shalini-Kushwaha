Headers are metadata/instructions attached to a request or response — the body carries the actual data. They're also where most other topics connect:

```text
HTTP Headers
    ├── Authentication -> Authorization
    ├── Cookies        -> Cookie / Set-Cookie
    ├── CORS           -> Origin / Access-Control-*
    ├── Caching        -> Cache-Control / ETag
    ├── Content        -> Content-Type / Accept
    └── Compression    -> Accept-Encoding / Content-Encoding
```

## Request vs Response

```text
Browser -> Request headers  -> Server
Server  -> Response headers -> Browser
```

## The Headers to Know

| Header | Direction | Meaning |
| --- | --- | --- |
| `Content-Type` | Either | Format of the body being sent |
| `Accept` | Request | Format wanted back |
| `Authorization` | Request | Credential the app explicitly attaches |
| `Cookie` | Request | Browser-attached credential/state |
| `Set-Cookie` | Response | Server asks the browser to store a cookie |
| `Origin` | Request | Where this browser request came from (CORS) |
| `Referer` | Request | Page that initiated the request — not reliable for auth |
| `User-Agent` | Request | Client/browser info — not reliable for security |
| `Cache-Control` | Response | How caches should treat this response |
| `ETag` | Response | Version identifier for cache validation |
| `If-None-Match` | Request | "Has this version changed?" — pairs with `ETag` to produce `304` |
| `Location` | Response | Redirect target, or where a newly created resource lives |
| `Content-Length` | Either | Body size in bytes |
| `Accept-Encoding` | Request | Compression formats the client understands |
| `Content-Encoding` | Response | Compression actually used |

## Two Nuances Worth Remembering

`Content-Type` = what I'm sending. `Accept` = what I want back.

`Authorization` is attached **explicitly** by your code; `Cookie` is attached **automatically** by the browser. That explicit-vs-automatic split is exactly why CSRF only threatens cookie-based auth.

```js
fetch("/api/me", { headers: { Authorization: `Bearer ${token}` } }) // you attach this
fetch("/api/me", { credentials: "include" })                        // browser attaches applicable cookies
```

## Debugging Checklist

**Request headers:** `Authorization` / `Cookie` / `Origin` / `Content-Type` / `Accept` — present and correct?
**Response headers:** `Set-Cookie` / `Access-Control-Allow-Origin` / `Cache-Control` / `ETag` — present and correct?

Most frontend networking bugs come down to one missing or wrong header on one side of that list.
