## 1. Sliding Window — Trigger

> Need to examine a contiguous range of an array/string and move it efficiently, instead of recomputing from scratch?

Two flavors:

- **Variable-size** — grows/shrinks with a condition (LC 3 — Longest Substring Without Repeating Characters)
- **Fixed-size** — always `pattern.length` (LC 567 — Permutation in String, LC 438 — Find All Anagrams)

## 2. The Window Is a Candidate, Not the Answer

The window holds the *current* candidate; a separate variable holds the *actual* answer.

- LC 3: window = current substring, answer = `maxLen`
- LC 438: window = current substring, answer = `result` (indices pushed when it matches)

## 3. Window Invariant

Something that must stay true while the window moves. For LC 3: *the window contains no duplicate characters* — tracked with a `Set`. A duplicate at `right` means shrinking from `left` until the invariant holds again.

## 4. Fixed Window + Frequency Map (LC 567 / LC 438)

Build a required frequency map from the pattern, then maintain a window frequency map of the same size. Instead of comparing both maps on every step, track one number:

```text
count = how many required characters currently have exactly the required frequency
count === map.size  →  match found
```

### Updating `count` on each slide

Before changing a character's frequency, note whether it was matched (`mf`); after changing it, check again (`cf`):

| Before (`mf`) | After (`cf`) | Effect      |
| -------------- | ------------ | ----------- |
| matched        | unmatched    | `count--`   |
| unmatched      | matched      | `count++`   |
| matched        | matched      | no change   |
| unmatched      | unmatched    | no change   |

```js
function slide(freq, required, ch, delta, count) {
  const before = freq.get(ch) === required.get(ch)
  freq.set(ch, (freq.get(ch) || 0) + delta)
  const after = freq.get(ch) === required.get(ch)
  if (before && !after) count--
  if (!before && after) count++
  return count
}
// on each step: slide(...,-1) for s[left] leaving, slide(...,+1) for s[right] entering
```

## 5. Why It's O(n)

`left` and `right` only ever move forward — never backward — so each element is processed a bounded number of times, even with a loop that looks nested.

| Problem                 | Time | Space |
| ------------------------ | ---- | ----- |
| LC 3                     | O(n) | O(k)  |
| LC 567 / LC 438          | O(n) | O(k)  |

(`k` = number of distinct characters tracked — constant for a fixed alphabet.)

## 6. The Questions to Ask

```text
Is the data contiguous?
Fixed or variable window?
What must always be true (the invariant)?
What state does the window carry?
What changes when left leaves, and when right enters?
```
